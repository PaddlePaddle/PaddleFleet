# AI Review

评审 PaddleFleet 代码的实际行为和跨模块影响。优先级、评论格式和发布策略由调用方决定；本 skill 只提供仓库级评审规则。

## 评审流程

1. 阅读 PR 描述和完整 diff，确认变更目标、影响范围及用户可见行为。
2. 按变更路径读取 [PaddleFleet 基础评审规则](references/review-rules.md) 中相关章节，不加载无关内容。
3. 使用 `rg` 追踪定义、调用方、配置入口、实现和测试；跨模块变更必须检查两端契约。
4. 对照完整函数和相关测试验证候选问题，确认可复现或有明确代码证据后再报告。
5. 评论应指出具体位置、影响、触发条件和修改方向；不报告无依据的猜测、纯风格偏好或泛化建议。

## 基本原则

- 正确性、安全和兼容性优先于格式与命名。
- 分布式、算子和数值路径必须同时检查前向/反向、边界条件及回退路径。
- 行为变化必须有与风险匹配的单卡或多卡测试。
- 本 skill 和规则使用简体中文；GitHub 评论语言遵循调用方配置。
