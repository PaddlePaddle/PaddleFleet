# AI Review

评审 PaddleFleet 代码的实际行为和跨模块影响。优先级、评论格式和发布策略由调用方决定；本 skill 只提供仓库级评审规则。

## 规则加载

加载本 skill 后、开始评审前，读取本 `SKILL.md` 同目录下 `references/` 中的全部 Markdown 文件。必须包含 [基础规则](references/base-rules.md)和[单测规则](references/unit-test-rules.md)；其他文件均为扩展规则，不按变更路径跳过加载。根据各规则声明的适用路径和触发条件决定是否应用。实体文件统一维护在仓库根目录 `skills/ai-review/`，Codex/Claude 的入口软链接共用这些文件。

## 评审流程

1. 按单测规则“PaddleFleet仓库模块”主表中的关键模块定位职责，使用 `rg` 追踪定义、调用方、配置入口、实现和测试；结合该模块的无卡/单卡/多卡要求及用例设计审查，并按模块内链接读取 `references/unit-test-antipatterns.md` 中相关反模式，核对反例、漏检原因及修正写法；跨模块变更检查两端契约。
2. 对照完整函数和相关测试验证候选问题，确认可复现或有明确代码证据后再报告。
3. 评论应指出具体位置、影响、触发条件和修改方向；测试问题说明哪项业务行为缺少验证、什么错误可能漏检，以及需要观察的结果。区分实际运行、静态核对和未验证部分，不报告无依据的猜测、纯风格偏好或泛化建议。

更具体的扩展规则优先于基础规则；规则冲突且无法由代码或仓库约定判定时，向维护者确认。

## 基本原则

- 正确性、安全和兼容性优先于格式与命名。
- 分布式、算子和数值路径按本次变更的契约检查相关前向/反向、边界条件及回退路径。
- 行为变化应有与风险匹配的无卡、单卡或多卡测试；按实际变更选择环境，缺硬件或全 skip 不算已验证。
- 本 skill 和规则使用简体中文；GitHub 评论语言遵循调用方配置。
